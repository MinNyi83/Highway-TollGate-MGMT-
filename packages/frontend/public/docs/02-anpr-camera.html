ISAPI Integration — Hikvision HTTP API

Hikvision cameras use the ISAPI (Internet Surveillance API) protocol for device management, ANPR queries, and snapshot retrieval. All endpoints use HTTP Basic Authentication over HTTP/HTTPS.

ISAPI Authentication

All ISAPI endpoints require HTTP Basic Authentication. The username and password are configured during camera initial setup via the Hikvision web interface.

# curl example — get device info via ISAPI
curl -s -u "admin:YourPassword123" \
  http://192.168.10.60/ISAPI/System/deviceInfo

# Response (XML):
<?xml version="1.0" encoding="UTF-8"?>
<DeviceInfoResponse>
  <deviceID>DS-2CD7A46G0-IZHS</deviceID>
  <serialNumber>DS-2CD7A46G0IZHS20260101AAGY00000</serialNumber>
  <model>DS-2CD7A46G0-IZHS</model>
  <firmwareVersion>V5.7.21</firmwareVersion>
  <deviceStatus>active</deviceStatus>
</DeviceInfoResponse>

ANPR Query via ISAPI

# Get confirmed ANPR plate captures
curl -s -u "admin:YourPassword123" \
  "http://192.168.10.60/ISAPI/Traffic/channels/1/anpr/picture/confirmed?searchID=1726000000000&startIndex=0&count=10"

# Response includes plate recognition results:
<TrafficPictureList>
  <TrafficPicture>
    <plateNumber>1A/23456</plateNumber>
    <confidence>98.5</confidence>
    <timeStamp>2026-09-13T10:30:15+06:30</timeStamp>
    <cameraID>CH1</cameraID>
    <imageUrl>/Traffic/pictures/20260913/103015_plate.jpg</imageUrl>
  </TrafficPicture>
</TrafficPictureList>
⚠️ Note: The searchID parameter accepts a Unix timestamp in milliseconds. Use Date.now() in JavaScript or $(date +%s%3N) in bash to generate it. Results are paginated — use startIndex and count parameters to retrieve all plates.

Snapshot Retrieval

# Get a single JPEG snapshot from channel 1
curl -s -u "admin:YourPassword123" \
  http://192.168.10.60/ISAPI/Streaming/channels/1/picture \
  -o snapshot.jpg

# Convert to base64 for API transport
curl -s -u "admin:YourPassword123" \
  http://192.168.10.60/ISAPI/Streaming/channels/1/picture \
  | base64 > snapshot_base64.txt

Physical Mounting — Angle Optimization

Correct camera angle is critical for >99% ANPR accuracy. A camera mounted too high or too low will produce distorted plates. Follow these specifications for optimal capture at vehicle speeds up to 120 km/h.

Overhead (Gantry) Mount — Recommended

Camera mounted 4.5m–6m above road surface on gantry arm, tilted 15°–25° from vertical toward approaching traffic.

    ⚠️  SIDE MOUNT LIMITATIONS:
    • Lower accuracy at speeds >60 km/h (oblique angle)
    • Requires wider field of view (2.8mm lens minimum)
    • Plate perspective distortion at close range
    • Not recommended for lanes >3.75m wide
⚠️ Critical Rules:
• Never mount the camera facing directly into the sun (use hood/shield if unavoidable)
• Ensure the plate fills 15–25% of the frame width for optimal OCR
• Avoid mounting where overhead signs or structures cast shadows on the plate zone
• Maintain minimum 6m capture distance for vehicles traveling above 60 km/h

RTSP Configuration — Video Streaming

RTSP (Real Time Streaming Protocol) provides live video feeds from the ANPR camera. TollGate uses RTSP for real-time plate visualization and recording. All Hikvision cameras use Digest Authentication for RTSP access.

RTSP URL Format

Stream TypeRTSP URLResolutionBitratePurpose
Main Stream rtsp://user:pass@IP:554/Streaming/Channels/101 2688×1520 (4MP) 4–8 Mbps ANPR processing + recording
Sub Stream rtsp://user:pass@IP:554/Streaming/Channels/102 704×576 (D1) 512 Kbps–1 Mbps Live preview / low bandwidth
HTTP Preview http://IP/Streaming/Channels/101/httpPreview 2688×1520 (4MP) Variable Browser-based preview
💡 Channel Numbering: Hikvision uses a 3-digit channel scheme: 101 = Channel 1 Main Stream, 102 = Channel 1 Sub Stream, 201 = Channel 2 Main Stream, etc. For single-camera ANPR, always use Channel 1 (101/102).

RTSP Stream Testing

# Test RTSP stream with ffplay (playback)
ffplay -rtsp_transport tcp \
  rtsp://admin:YourPassword123@192.168.10.60:554/Streaming/Channels/101

# Test with VLC
vlc rtsp://admin:YourPassword123@192.168.10.60:554/Streaming/Channels/101

# Capture a single frame via FFmpeg
ffmpeg -rtsp_transport tcp -i \
  rtsp://admin:YourPassword123@192.168.10.60:554/Streaming/Channels/101 \
  -frames:v 1 -q:v 2 capture.jpg

# Record 10-second clip for testing
ffmpeg -rtsp_transport tcp -i \
  rtsp://admin:YourPassword123@192.168.10.60:554/Streaming/Channels/101 \
  -t 10 -c copy test_clip.mp4

Backend Integration — API Commands

The TollGate backend provides REST API endpoints for ANPR camera management, plate query, and toll event creation. These curl commands demonstrate how to test and integrate ANPR data with the central HQ server.

Device Management — Camera Registration

  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \

    "plazaId": "plaza-yangon-01",
    "type": "ANPR_CAMERA",
    "name": "ANPR Lane 1",
    "ipAddress": "192.168.10.60",
    "port": 80,

      "username": "admin",
      "password": "YourPassword123",
      "useHttps": false,

  "success": true,
  "data": {
    "id": "dev-anpr-001",

    "status": "registered"

Toll Event with ANPR Plate

# Create a toll event with both RFID tag and ANPR plate
curl -X POST http://192.168.100.101:3000/api/toll-events \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "vehicleId": "veh-001",
    "plazaId": "plaza-yangon-01",
    "rfidTagId": "E200 3411 B802 0160 2260 1254",
    "anprPlate": "1A/23456",
    "laneNumber": 1,
    "direction": "entry",
    "amount": 2000
  }'

# Response — note the cross-verification:
{
  "success": true,
  "data": {
    "id": "evt-20260913-001",
    "rfidTagId": "E200 3411 B802 0160 2260 1254",
    "anprPlate": "1A/23456",
    "plateVerified": true,
    "amount": 2000,
    "status": "completed"
  }
}
✅ Cross-Verification: The backend automatically cross-checks the ANPR plate number against the vehicle's registered plate. If they don't match, a RFID_ANPR_MISMATCH violation is created for manual review. This prevents tag cloning and plate fraud.

Query ANPR Event History

Troubleshooting

Common ANPR camera issues and their resolutions. Most problems are caused by incorrect IP configuration, PoE power issues, or camera angle misalignment.

SymptomLikely CauseFix
Camera unreachable Wrong IP, PoE port dead, cable fault Check PoE switch port LED, swap cable, factory reset camera via reset button (hold 10s)
ISAPI 401 Unauthorized Wrong username/password, HTTP digest mismatch Reset camera to factory defaults, reconfigure credentials via web UI on port 80
RTSP connection refused RTSP disabled, wrong port, firewall blocking Enable RTSP in camera Network → Advanced settings, verify port 554, check iptables
Low plate accuracy (<90%) Wrong angle, motion blur, poor lighting Adjust vertical angle to 15°–25°, increase shutter speed to 1/1000s, enable WDR
Plates not detected at night IR reflection, IR cut filter stuck, exposure too low Check IR illuminator alignment, enable auto IR, increase exposure time, clean lens
Duplicate plate reads Dedup window too small, slow vehicle speed Increase deduplicationWindow to 3000ms, check camera trigger zone width
PoE switch port not powering Insufficient PoE budget, cable too long Check total PoE load vs budget, reduce cable length below 80m, use managed PoE switch
Camera reboots randomly Insufficient PoE power, overheating, firmware bug Verify PoE class 3 support, check operating temp, update firmware to latest version
ANPR results delayed Poll interval too long, network latency, ISAPI timeout Reduce captureInterval to 500ms, check network latency, increase timeout to 15s
Backend returns empty plate Camera not returning ANPR data, channel misconfigured Verify ISAPI ANPR endpoint directly, check channelId matches camera channel number
