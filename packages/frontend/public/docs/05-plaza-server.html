Installation Steps

Step-by-step setup from bare Raspberry Pi to running plaza server

Step 1: Raspberry Pi OS Setup

  1. Flash Raspberry Pi OS Lite (64-bit)

    Download from raspberrypi.com/software. Use Raspberry Pi Imager with SSH enabled and WiFi pre-configured.

    # On your workstation — flash SD card
rpi-imager --os raspios-lite-arm64 --storage /dev/sdX

  2. First Boot & System Update

    SSH into the Pi, update packages, and set timezone.

    # SSH in
ssh pi@<PLAZA_IP>

# Update system
sudo apt update && sudo apt upgrade -y

# Set timezone
sudo timedatectl set-timezone Asia/Yangon

# Set hostname
sudo hostnamectl set-hostname plaza-01

# Reboot
sudo reboot

  3. Configure Static IP & VLAN

    Assign static IP for the management network and create a VLAN for device isolation.

    # Edit dhcpcd config
sudo nano /etc/dhcpcd.conf
    # Management network (eth0)
interface eth0
static ip_address=192.168.100.51/24
static routers=192.168.100.1
static domain_name_servers=8.8.8.8

# Device VLAN (eth0.100)
interface eth0.100
static ip_address=10.10.100.1/24

  4. Expand Storage & Optimize for SSD

    Move Docker root to USB SSD for performance and reliability.

    # Expand filesystem
sudo raspi-config --expand-rootfs

# Format SSD as ext4
sudo mkfs.ext4 /dev/sda1

# Mount SSD
sudo mkdir -p /mnt/ssd
sudo mount /dev/sda1 /mnt/ssd

# Move Docker to SSD
sudo systemctl stop docker
sudo mv /var/lib/docker /mnt/ssd/docker
sudo ln -s /mnt/ssd/docker /var/lib/docker

Step 2: Docker & Docker Compose

  1. Install Docker via convenience script

    # Install Docker
curl -fsSL https://get.docker.com | sh

# Add pi user to docker group
sudo usermod -aG docker pi

# Log out and back in, then verify
docker --version
docker compose version

  2. Configure Docker daemon

    Set logging driver, storage driver, and resource limits.

    sudo nano /etc/docker/daemon.json
    {
  "storage-driver": "overlay2",
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "dns": ["8.8.8.8", "8.8.4.4"],
  "log-level": "warn"
}
    sudo systemctl restart docker

Step 3: Deploy Plaza Server

  1. Clone repository and configure

    # Clone repo
cd /opt
sudo git clone https://github.com/your-org/TollGate-RFID.git
sudo chown -R pi:pi /opt/TollGate-RFID

# Create plaza config
cp packages/plaza-server/.env.example packages/plaza-server/.env
nano packages/plaza-server/.env
    # .env file
PLAZA_ID=plaza-01
PLAZA_NAME="Yangon Toll Plaza"
HQ_SERVER_URL=https://192.168.100.101:3000
HQ_API_KEY=your-api-key-here
SYNC_INTERVAL=30000
POSTGRES_PASSWORD=secure-password-here
REDIS_PASSWORD=redis-password-here
NODE_ENV=production

  2. Launch with Docker Compose

    # Build and start all containers
cd /opt/TollGate-RFID
docker compose -f packages/plaza-server/docker-compose.yml up -d --build

# Verify all containers running
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
    NAMES                STATUS              PORTS
plaza-api            Up 2 minutes        0.0.0.0:4000->4000/tcp
plaza-sync           Up 2 minutes        4001/tcp
plaza-db             Up 2 minutes        5434/tcp
plaza-redis          Up 2 minutes        6379/tcp
plaza-nginx          Up 2 minutes        0.0.0.0:80->80/tcp

  3. Run database migrations

    # Initialize plaza database schema
docker exec plaza-api npx prisma migrate deploy --schema=prisma/schema.plaza.prisma

# Seed initial plaza config
docker exec plaza-api npx prisma db seed

  4. Verify deployment

    # Health check
curl -s http://localhost:4000/api/health | python3 -m json.tool

# Expected output
{
  "status": "healthy",
  "plaza": "plaza-01",
  "uptime": 120,
  "db": "connected",
  "hq_reachable": true
}
✅
Deployment Complete: The plaza server is now running. Connect RFID readers, ANPR cameras, and barrier gates to their respective interfaces. The admin panel is available at https://<PLAZA_IP>.

Sync Protocol

Bidirectional data flow between plaza and HQ with conflict resolution

The sync engine runs as a background container (plaza-sync), processing queued events and pulling updates from HQ. Data packets flow in real-time — watch the animation below.

📡 BI-DIRECTIONAL SYNC PROTOCOL — LIVE DATA FLOW
🍓 Plaza Server :4000
🏢 HQ Server :3000
PUSH
PULL
⬆ Toll Events · Device Status ⬇ Config Updates · Rate Tables
◀
▶
Push: Plaza → HQ (events, status)
Pull: HQ → Plaza (config, rates)

Push (Plaza → HQ)

Event-driven, every 30s

Pushes new toll events, device status, and local anomalies to HQ. Uses optimistic locking with last_modified timestamps.

// Push payload structure
{
  "plaza_id": "plaza-01",
  "events": [
    {
      "id": "evt_a1b2c3",
      "rfid_tag": "AB:CD:EF:12",
      "plate_number": "1K-1234",
      "amount": 5000,
      "timestamp": "2026-09-13T08:30:00Z",
      "synced": false
    }
  ],
  "device_status": { ... }
}

Pull (HQ → Plaza)

On-demand + periodic

Pulls configuration updates, toll rate changes, and account balances from HQ. Pulls also trigger conflict resolution for any modified records.

// Pull response structure
{
  "config": {
    "toll_rates": [ ... ],
    "plaza_settings": { ... },
    "rfid_whitelist": [ ... ]
  },
  "accounts": [
    {
      "rfid_tag": "AB:CD:EF:12",
      "balance": 85000,
      "status": "active"
    }
  ],
  "conflicts": [ ... ]
}
🔄
Conflict Resolution: Uses Last-Write-Wins (LWW) strategy. When both plaza and HQ modify the same record, the last_modified timestamp determines the winner. Conflicts are logged and an admin notification is triggered for manual review if needed.

Offline Operation

Graceful degradation when HQ connection is unavailable

The plaza server is designed as an offline-first edge node. It continues processing toll events even when the network to HQ is down. Events are queued locally and synced when connectivity is restored.

📋 Offline Queue Behavior

StateDescriptionAction
ONLINEHQ reachableReal-time push/pull
DEGRADEDHigh latency (>5s)Reduce sync frequency
OFFLINEHQ unreachableQueue events locally
RECOVERINGConnection restoredBurst sync queue

⚙️ Queue Configuration

# /opt/tollgate/config/sync.yaml
sync:
  interval_ms: 30000
  retry_backoff: [1000, 5000, 30000, 60000]
  max_queue_size: 10000
  batch_size: 50
  conflict_strategy: "last-write-wins"
  offline_capable: true
  local_cache_ttl: 3600
⚠️
Storage Limit: The queue stores events in the local PostgreSQL database. At 500 bytes per event, the 10,000-event limit uses ~5MB. If the queue fills, oldest unsynced events are archived to disk. After 72 hours offline, a manual sync intervention is recommended.

Troubleshooting

Common issues and their solutions

IssueSymptomsSolution
DB connection refused API returns 500, ECONNREFUSED Run docker restart plaza-db. Check volume mount: ls /mnt/ssd/docker/volumes/
Sync stuck (queue depth growing) Queue depth > 0 for > 5 min Check HQ reachability: curl -s http://192.168.100.101:3000/api/health. Restart sync: docker restart plaza-sync
RFID reader not detected device_status.rfid_reader: "disconnected" Check VLAN config: ping 10.10.100.10. Verify port: nc -zv 10.10.100.10 5000. Restart RFID service.
ANPR camera offline Camera status shows disconnected Check PoE switch: ping 10.10.100.20. Verify RTSP stream: ffprobe rtsp://admin:pass@10.10.100.20:554
Barrier gate unresponsive Barrier status: error Check serial cable: ls /dev/ttyUSB*. Verify baud rate in config. Power cycle barrier unit.
High CPU temperature Temp > 70°C, throttling active Check fan: vcgencmd measure_temp. Ensure active cooling. Reduce sync frequency if sustained.
Docker containers not starting docker ps shows no containers Check logs: docker compose logs -f. Verify disk space: df -h. Rebuild: docker compose up -d --build
SD card corruption Boot failures, read-only filesystem Boot from SSD if configured. Re-flash SD card. Enable dwc_otg.fiq_enable=1 in /boot/firmware/cmdline.txt
