Overview — Supported RFID Reader Models

TollGate supports three primary UHF RFID reader families. All models use EPC Gen2 (ISO 18000-6C) protocol operating in the 860–960 MHz band. Model selection depends on deployment environment, range requirements, and budget.

Impinj R420

Industrial Fixed Reader

Premium enterprise-grade reader with best-in-class sensitivity. Ideal for high-speed highway lanes requiring 12m read range at 60+ km/h.

TCP/IP 12 dBi Recommended

ZKTeco UHF300

Mid-Range Fixed Reader

Cost-effective reader with TCP/IP and optional serial interface. Good balance of performance and price for standard 4-lane plazas.

TCP/IP RS232 8 dBi

Custom Serial Reader

UART/RS232 Generic

Budget serial-only reader connected directly to Raspberry Pi GPIO UART. Lower range but simplest wiring for basic installations.

RS232 Only 6 dBi 3–5m range

Connection Types — TCP/IP vs Serial vs ZKTeco

Choose the right connection method based on distance, speed, and existing infrastructure. TCP/IP is the recommended method for all new highway deployments.

🔌 TCP/IP (Ethernet)

  • 100m+ cable run distance
  • PoE power — single cable
  • High-speed data transfer
  • Remote firmware updates
  • Multiple readers per switch
  • Standard network monitoring
Recommended Port 5000

🔌 Serial (RS232/UART)

  • Simple 3-wire connection
  • Direct RPi GPIO wiring
  • No network config needed
  • Lower latency (no TCP stack)
  • Max 15m cable length
  • No PoE — separate power
  • Single reader per UART
9600 baud Limited range

🔌 ZKTeco Direct

  • TCP/IP + RS232 combo
  • Built-in antenna option
  • ZKTeco SDK available
  • Good price/performance
  • Vendor-locked firmware
  • Less community support
  • Shorter range than Impinj
Hybrid Dual mode

Wiring Diagrams — Serial & TCP Connections

Follow the exact pinouts below. Incorrect wiring is the #1 cause of reader initialization failure. Double-check power polarity before connecting data lines.

Serial Connection (RS232 to Raspberry Pi)

Direct 3-wire connection between RFID reader serial port and RPi GPIO UART pins.

📡 RFID Reader (DB9 Male)

Pin 2 — RXD← Read Data In
Pin 3 — TXD→ Write Data Out
Pin 5 — GND⏚ Ground
Power: 12V DC 2A barrel jack

🍓 Raspberry Pi 4 GPIO

GPIO 10 (TXD)→ TX Out
GPIO 15 (RXD)← RX In
GPIO 14 (GND)⏚ Ground
UART via /dev/ttyAMA0 @ 9600 baud
⚡ CRITICAL: Cross TX/RX lines — Reader TXD connects to RPi RXD, and vice versa. Never connect 12V power to GPIO pins. Use a level shifter if the reader outputs 5V TTL instead of 3.3V.

TCP/IP Connection (Ethernet with PoE)

Recommended for highway deployments. Single cable carries data and power via IEEE 802.3af PoE.

Network Configuration — VLAN & Firewall

Isolate RFID readers on a dedicated VLAN to prevent unauthorized access and reduce broadcast traffic. This is a security requirement for all production deployments.

VLAN Setup

Create a dedicated VLAN (e.g., VLAN 10) for all IoT/sensor devices. Tag the port connecting to each RFID reader as an access port on VLAN 10.

# Switch port config (Cisco IOS example)
interface GigabitEthernet0/1
 description RFID Reader Lane 1
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
 no shutdown

# VLAN definition
vlan 10
 name RFID_SENSOR_NET

Firewall Rules

Restrict traffic to only necessary ports. RFID readers should only communicate with the RPi edge server, never directly to the internet.

# iptables rules for RPi edge gateway
# Allow RFID reader on port 5000
iptables -A INPUT -s 192.168.10.50 -p tcp \
  --dport 5000 -j ACCEPT

# Allow outbound to HQ server only
iptables -A OUTPUT -d 192.168.100.101 -p tcp \
  --dport 3000 -j ACCEPT

# Block all other external traffic
iptables -A INPUT -j DROP

Static IP Assignment

Assign static IPs to all RFID readers and RPi gateways. DHCP is not recommended for production IoT infrastructure.

SNMP Monitoring

Enable SNMP v2c on readers for uptime monitoring via the HQ server. Set community string to a non-default value.

# On RPi — monitor reader port
snmpwalk -v2c -c "tollgate_ro" \
  192.168.10.50:161 system

# Cron job: check every 5 min */5 * * * *
ping -c 3 192.168.10.50 || \
  logger "ALERT: RFID reader offline"
⚠️ SNMP: Use SNMPv3 in production for authentication and encryption.

Testing & Verification

Verify each component before going live. Run these tests in order — skipping any step may cause silent failures during peak traffic.

1

Ping Test — Network Reachability

Confirm the RFID reader responds on the network before configuring any software.

# From RPi edge gateway
ping -c 5 192.168.10.50

# Expected output:
64 bytes from 192.168.10.50: icmp_seq=1 ttl=64 time=0.89 ms
2

TCP Port Check — Service Availability

Verify the reader's TCP service is listening on port 5000.

# Check port 5000 is open
nc -zv 192.168.10.50 5000

# Expected output:
Connection to 192.168.10.50 5000 port [tcp/*] succeeded!

# Or use curl for HTTP-based readers
curl -s http://192.168.10.50:5000/status | head -20
3

Tag Read Test — Functional Verification

Place a known RFID tag in front of the antenna and verify it is read correctly.

# Python quick test script
python3 -c "
import socket
s = socket.socket()
s.connect(('192.168.10.50', 5000))
s.send(b'READ\r\n')
resp = s.recv(1024)
print('Tag ID:', resp.decode().strip())
s.close()
"

# Expected: Tag ID like E200 3411 B802 0160 2260 1254
4

Integration Test — Full Pipeline

Walk a vehicle through the lane (or simulate) and verify the complete read → process → log flow.

# Check backend API received the event
curl -s http://localhost:3000/api/toll-events?limit=5 \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool

# Check RPi local sync queue
curl -s http://localhost:4000/api/sync/status | \
  python3 -m json.tool

# Expected: recent event with matching tag ID

Maintenance Schedule

Regular maintenance prevents 90% of field failures. Follow this schedule for maximum uptime and reader longevity.

DAILY
Automated Health Check

RPi ping monitor verifies reader is online. Alert sent if unreachable for >2 minutes. No manual intervention needed.

WEEKLY
Visual Inspection

Check antenna cable connections for corrosion or looseness. Inspect weatherproof enclosures for moisture ingress. Verify LED status indicators.

MONTHLY
Read Rate Performance Test

Walk-test with 20 known tags across the full lane width. Record read rate percentage. Expected: >99% within 2 passes. If below 95%, check antenna alignment.

QUARTERLY
Firmware Update & Deep Clean

Update reader firmware to latest stable version. Clean antenna face with isopropyl alcohol. Check coax cable for moisture in connectors. Recalibrate if needed.

ANNUALLY
Full System Overhaul

Replace weatherproof gaskets and cable seals. Run full antenna gain test. Replace any corroded connectors. Update SSH keys and SNMP community strings. Full backup of reader config.
